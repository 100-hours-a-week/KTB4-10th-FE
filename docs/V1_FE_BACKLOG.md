# V1 프론트엔드 작업 순서

## 기준

- 화면은 Figma V1 프레임을 기준으로 구현한다.
- 모바일에서는 기기 너비를 사용하고, 데스크톱·태블릿에서는 모바일 앱 셸을 중앙에 표시한다.
- V1부터 V3까지 데스크톱 전용 확장 레이아웃은 구현하지 않는다.
- API는 백엔드 최신 `dev`에서 실제 구현된 회원·인증·인가와 가이드북 API를 우선 사용한다.
- 관광 지도처럼 백엔드 계약이 아직 없는 화면은 API 계약이 확정될 때까지 UI 뼈대만 먼저 만들지 않는다.
- 한 Issue는 가능하면 한 사람이 1~2일 안에 리뷰 가능한 크기로 나눈다.

## 먼저 구현할 묶음

첫 묶음은 로그인 화면을 예쁘게 만드는 것보다 실제 세션 계약을 연결하는 데 집중한다.

1. 공통 API 응답과 CSRF 처리
2. 카카오 로그인 시작·완료·실패
3. `/members/me` 기반 상태 라우팅
4. 취향 선택과 ACTIVE 전환

이 묶음이 끝나면 사용자가 실제 로그인 후 가이드북 기능으로 진입할 수 있다. 이후 가이드북 생성 요청과 상태 폴링을 연결한다.

## 보류 범위

- 지도·관광 콘텐츠: 백엔드 조회 API와 클러스터 계약 확정 후 진행
- 평가·랭킹·결제: V2/V3 요구사항과 API가 구현될 때 진행
- SSE, Web Push, FCM: V1 인앱 알림 조회와 별개이며 전달 채널 요구가 확정될 때 진행
- 전역 상태 라이브러리: 서로 먼 화면이 같은 클라이언트 상태를 실제로 공유할 때 검토
- 서버 상태 라이브러리: 캐시·재검증·중복 요청 관리가 반복 구현될 때 검토

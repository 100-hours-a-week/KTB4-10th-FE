# V1 프론트엔드 관측성 운영

GA는 주요 사용자 행동의 수와 흐름을, Sentry는 프론트엔드 예외와 원본 코드 위치를 확인한다. Microsoft Clarity는 실제 사용자 세션을 확인하는 별도 도구이며 이 문서의 구현 범위에 포함하지 않는다.

## 1. Google Analytics 이벤트

사용자 행동 이벤트는 production build에서만 전송한다. 이메일, 닉네임, 회원 ID, OAuth code, 세션·CSRF 값과 자유 입력문은 전송하지 않는다.

| 이벤트 | 기록 시점 | 파라미터 |
| --- | --- | --- |
| `login` | Kakao OAuth 완료 후 회원·취향 조회 성공 | `method: kakao` |
| `guidebook_generate_start` | 새로운 멱등키로 생성 요청을 시작 | 없음 |
| `guidebook_generate_accepted` | BE가 생성 작업을 정상 접수 | 없음 |
| `guidebook_generate_success` | polling에서 최초 `COMPLETED` 확인 | `generation_time_ms` |
| `guidebook_generate_fail` | polling에서 최초 `FAILED` 확인 | `generation_time_ms` |

- 로그인 버튼 클릭과 OAuth 실패는 `login`으로 기록하지 않는다.
- 응답 유실 후 같은 멱등키로 다시 요청할 때 `guidebook_generate_start`를 중복 기록하지 않는다.
- `PENDING`, `PROCESSING` polling은 이벤트를 만들지 않는다.
- `generation_time_ms`는 생성 요청 시작부터 FE가 최종 상태를 확인할 때까지의 사용자 대기 시간이다. 순수 AI 처리 시간과 다르다.
- 진행 작업과 시작 시각은 회원별 localStorage 작업 항목에 함께 보관한다. 최종 상태 기록 여부도 보관해 새로고침 뒤 같은 종결 이벤트가 중복되지 않게 한다.

## 2. Sentry Error Monitoring

앱 렌더 전에 Sentry를 초기화한다. production이면서 `VITE_SENTRY_DSN`이 있을 때만 전송한다.

Sentry SDK에는 다음 수집 제한을 적용한다.

- 사용자 정보 수집 비활성화 및 event의 `user` 제거
- cookie, HTTP header와 request·response body 수집 비활성화
- URL query parameter 수집 비활성화
- event request URL과 breadcrumb URL에서 query 제거

오류 메시지나 추가 context를 직접 전송할 때에도 개인정보와 인증값을 넣지 않는다.

## 3. 환경변수와 역할

| 값 | 사용 위치 | 담당 | 저장 원칙 |
| --- | --- | --- | --- |
| `VITE_SENTRY_DSN` | 브라우저 Sentry SDK | 클라우드 | GitHub Secret/CD에서 build에 전달 |
| `SENTRY_AUTH_TOKEN` | Vite source map upload | 클라우드 | GitHub Secret 전용, `VITE_` 금지 |
| Organization `kgb-w6` | Vite plugin | FE 코드 | 공개 설정 |
| Project `kgb-front` | Vite plugin | FE 코드 | 공개 설정 |

- FE는 SDK 초기화, 개인정보 최소화, Vite plugin과 hidden source map 설정을 관리한다.
- 클라우드 담당자는 Sentry 계정·프로젝트, 두 GitHub Secret, 실제 업로드와 배포 비노출을 관리한다.
- 실제 값은 `.env.example`, Issue, PR, 로그와 코드에 기록하지 않는다.

## 4. Source Map 배포 계약

`SENTRY_AUTH_TOKEN`이 있는 production build에서만 hidden source map을 생성한다. Sentry Vite plugin은 map을 `kgb-w6/kgb-front`에 업로드하고 성공 후 `dist/**/*.map`을 삭제한다.

토큰이 없는 로컬·테스트·PR build는 source map을 만들지 않으므로 Sentry 계정 없이도 기존 검사를 수행할 수 있고, map 파일이 실수로 S3에 배포되지 않는다.

```text
Vite build
  → hidden source map 생성(token이 있을 때만)
  → Sentry 업로드
  → dist map 삭제
  → S3 sync
  → CloudFront 배포
```

## 5. 배포 확인

클라우드 담당자는 최초 적용 시 다음을 확인한다.

1. GitHub Actions Secret에 `VITE_SENTRY_DSN`, `SENTRY_AUTH_TOKEN`을 등록한다.
2. `main` 배포의 build log에서 Sentry 업로드 성공을 확인한다. 토큰 원문은 로그에 출력하지 않는다.
3. S3 배포 대상과 CloudFront URL에 `.map` 파일이 남지 않았는지 확인한다.
4. 운영 화면에서 식별정보가 없는 테스트 Error를 한 번 발생시킨다.
5. Sentry event가 production 환경으로 수집되고 stack trace가 TS/TSX 원본 파일과 줄을 가리키는지 확인한다.
6. event의 user, cookie, authorization·CSRF header, request body와 URL query가 수집되지 않았는지 확인한다.

GA는 Realtime 또는 DebugView에서 `login`과 가이드북 생성 이벤트 이름·횟수만 확인한다. 운영 검증을 위해 개인정보나 식별자를 임시 파라미터로 추가하지 않는다.

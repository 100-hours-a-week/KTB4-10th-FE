# 프로젝트 요구사항 분석

> V1 개발을 위한 프론트엔드 관점의 초안이다. 기획·백엔드 API 변경 시 함께 갱신한다.

## 1. 목표

- 카카오 로그인 후 회원 상태에 맞는 화면으로 이동한다.
- 사용자가 취향을 선택하고 AI 가이드북을 생성·조회할 수 있게 한다.
- 설정, 정책, 알림, 로그아웃·탈퇴 등 기본 회원 기능을 제공한다.
- 모바일 웹을 우선하되 데스크톱에서도 기능이 깨지지 않게 한다.

## 2. V1 사용자 흐름

1. 사용자가 카카오 로그인을 시작한다.
2. 로그인 완료 후 `GET /api/v1/members/me`로 상태를 확인한다.
3. `ONBOARDING` 회원은 취향을 저장하고 `ACTIVE`로 전환한다.
4. `ACTIVE` 회원은 맵·정보·가이드·마이페이지를 이용한다.
5. 가이드북 생성 요청 후 진행 상태를 조회하고, 완료되면 결과를 확인한다.

## 3. 기능 요구사항

| ID | 영역 | 요구사항 | V1 상태 |
|---|---|---|---|
| FE-FR-01 | 인증 | 카카오 OAuth 시작·완료·실패 화면을 제공한다. | 필수 |
| FE-FR-02 | 인가 | 비로그인, `ONBOARDING`, `ACTIVE` 상태별 접근을 제어한다. | 필수 |
| FE-FR-03 | 취향 | 옵션 조회, 선택 규칙 검증, 전체 저장을 제공한다. | 필수 |
| FE-FR-04 | 가이드북 | 생성 조건 입력, 생성 요청, 상태 조회·재시도, 목록·상세·삭제를 제공한다. | 필수 |
| FE-FR-05 | 회원 | 내 정보·설정·정책·알림·로그아웃·탈퇴 화면을 제공한다. | 필수 |
| FE-FR-06 | 탐색 | 지도와 관광 콘텐츠를 조회한다. | API 확정 후 |
| FE-FR-07 | 평가·결제 | 평가·랭킹·생성권 결제를 제공한다. | V2/V3 |

## 4. 비기능 요구사항

- 보안: 세션 쿠키와 CSRF 계약을 준수하고 비밀값을 브라우저 번들에 넣지 않는다.
- 사용성: 로딩·빈 결과·오류·재시도 상태를 모든 비동기 화면에 표시한다.
- 접근성: 키보드 조작, 레이블, 포커스, 색상 외 상태 표현을 지원한다.
- 성능: 초기 번들을 작게 유지하고 화면 단위 지연 로딩을 검토한다.
- 품질: 핵심 분기와 상태 변경 요청을 자동 테스트한다.

## 5. 공통 API 계약

- 세션 쿠키 전송을 위해 `withCredentials=true`를 사용한다.
- 변경 요청은 `XSRF-TOKEN` 값을 `X-XSRF-TOKEN` 헤더로 전송한다.
- 응답은 공통 `message`, `data`, `error` 구조로 해석한다.
- `401`은 로그인 필요, `403`은 권한 또는 CSRF 오류를 구분해 처리한다.

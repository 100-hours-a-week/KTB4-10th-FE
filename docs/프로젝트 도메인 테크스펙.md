# 프로젝트 도메인 테크스펙

> 화면 코드 작성 전에 책임과 주요 상태를 합의하기 위한 V1 초안이다.

## 1. 인증·회원

- 책임: 카카오 로그인 이동, 로그인 결과 처리, 현재 회원 조회, 로그아웃·탈퇴
- 주요 상태: `anonymous`, `checking`, `ONBOARDING`, `ACTIVE`, `error`
- 규칙: 화면에서 회원 ID를 임의로 만들지 않고 세션으로 식별한다.
- 실패 처리: `401`은 로그인으로 이동하고, `403`은 CSRF 재조회 후 재시도 가능 여부를 판단한다.

## 2. 취향

- 책임: 대분류·중분류·여행 스타일 옵션 조회와 선택, 기존 취향 조회, 전체 저장
- 규칙: 대분류와 중분류는 필수, 여행 스타일은 선택이며 서버 계약의 개수 제한을 따른다.
- 저장: 부분 수정이 아닌 현재 선택 전체를 `PUT`으로 전달한다.
- 완료: 저장 응답의 회원 상태가 `ACTIVE`인지 확인한 뒤 메인으로 이동한다.

## 3. 가이드북

- 책임: 조건 입력, 멱등한 생성 접수, 작업 상태 조회, 재시도, 목록·상세·삭제
- 생성 상태: `PENDING/PROCESSING/COMPLETED/FAILED/CANCELED` 서버 Enum을 사용한다.
- 폴링: App 전역에서 응답 완료 2초 후 조회하며 내부 화면 전환에도 유지한다. 종료 상태·조회 오류·앱 종료·로그인 화면 이동 시 중단한다.
- HTML: 서버 원문을 sanitize하지 않고 sandbox iframe의 srcDoc으로 표시한다.
- 구현 계약과 미지원 범위는 [가이드북 V1 구현](./GUIDEBOOK_IMPLEMENTATION.md)을 따른다.

## 4. 알림·정책·설정

- 알림: 페이지 조회, 개별 삭제, 전체 삭제를 지원한다. V1은 실시간 푸시 전달과 구분한다.
- 정책: 이용약관·개인정보 처리방침 목록과 상세를 표시한다.
- 설정: `push_enabled`를 조회·변경하되 실제 Web Push 도입 전에는 수신 의사 설정으로 취급한다.

## 5. 탐색·관광 콘텐츠

- 책임: 지도 범위 내 관광 콘텐츠, 상세, 관심 장소를 표시한다.
- 현재 상태: 백엔드 API와 지도 SDK가 확정된 후 상세 테크스펙을 작성한다.

## 6. 공통 의사코드

```text
화면 진입
  -> 필요한 API 요청
  -> loading 표시
  -> 성공이면 DTO를 화면 모델로 변환
  -> 빈 결과면 empty 표시
  -> 401이면 로그인 경로로 이동
  -> 403이면 권한/CSRF 원인을 구분
  -> 그 외 실패면 오류와 재시도 표시
  -> 화면 이탈 시 진행 중 요청·타이머 정리
```

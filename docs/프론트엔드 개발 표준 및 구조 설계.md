# 프론트엔드 개발 표준 및 구조 설계

> 팀원이 같은 기준으로 병렬 작업하기 위한 최소 규칙이다.

## 1. 디렉터리

```text
src/
├── app/                 # 앱 시작, Router, 전역 Provider
├── pages/               # URL 단위 조합 화면
├── features/            # auth, preference, guidebook 등 기능 단위
├── shared/
│   ├── api/             # Axios, 공통 응답·오류 타입
│   ├── config/          # 환경변수와 라우트
│   ├── ui/              # 재사용이 확인된 공통 UI
│   └── lib/             # 도메인에 속하지 않는 유틸리티
├── styles/
└── test/
```

- `pages`는 조합과 라우팅을 담당하고 비즈니스 로직을 오래 보관하지 않는다.
- 기능 전용 코드는 `features/<domain>`에 둔다.
- 두 곳 이상에서 실제 재사용되기 전에는 `shared`로 올리지 않는다.

## 2. 작성 규칙

- TypeScript의 `strict` 설정을 유지하고 `any` 사용 시 이유를 남긴다.
- 서버 DTO와 화면에서 쓰는 파생 모델을 필요에 따라 분리한다.
- API 호출은 컴포넌트에 흩뿌리지 않고 기능별 모듈에 모은다.
- 문자열·URL·저장소 키는 의미 있는 상수로 관리한다.
- 로딩, 성공, 빈 결과, 오류 상태를 빠뜨리지 않는다.
- 사용자에게 표시되는 문구는 한국어로 통일한다.

## 3. 모바일 웹 앱 레이아웃

- 모든 페이지는 공통 `AppShell` 안에서 렌더링한다.
- `AppShell`은 모바일에서 `width: 100%`, 데스크톱·태블릿에서 모바일 기준 최대 폭과 `margin: 0 auto`를 사용한다.
- 정확한 최대 폭은 Figma V1 기준 프레임 폭을 확인해 공통 토큰 하나로 확정한다.
- V1부터 V3까지 데스크톱 화면 폭에 맞춰 콘텐츠를 확장하거나 다단 레이아웃으로 바꾸지 않는다.
- 전체 화면 높이는 `100dvh`를 우선 사용하고 호환성을 위한 `100vh` fallback을 둔다.
- 상·하단 고정 UI에는 `env(safe-area-inset-top)`과 `env(safe-area-inset-bottom)`을 고려한다.
- 콘텐츠가 앱 셸 밖으로 가로 스크롤되지 않게 하고, 지도·모달·바텀시트도 같은 폭 경계를 따른다.
- 기본 지원 브라우저는 최신 Chrome, Safari, Edge이며 Internet Explorer용 폴리필과 별도 CSS는 작성하지 않는다.

## 4. 세션·CSRF 규칙

- 인증 정보는 JavaScript 저장소에 별도 복제하지 않는다.
- `KGB_SESSION`은 쿠키로만 전달하고 Axios의 `withCredentials`를 유지한다.
- 상태 변경 전에 CSRF 쿠키를 준비하고 `X-XSRF-TOKEN` 헤더를 보낸다.
- `localhost`와 `127.0.0.1`을 섞지 않는다.

## 5. 테스트 기준

- 유틸리티: 입력·경계값 단위 테스트
- 컴포넌트: 사용자 클릭과 화면 결과 중심 테스트
- API 연결: 성공, 대표 오류, 권한 상태 테스트
- 핵심 흐름: 로그인 → 취향 저장 → 메인 진입 브라우저 E2E
- 화면: 대표 모바일 viewport, iOS 안전 영역, 넓은 데스크톱에서 중앙 모바일 앱 셸 확인

모든 내부 구현을 테스트하지 않고, 실패 시 사용자 흐름이 깨지는 계약을 우선한다.

## 6. Git 협업

- `dev`에서 Issue 단위 브랜치를 만든다.
- 한 PR은 하나의 목적을 유지하고 리뷰 가능한 크기로 나눈다.
- 커밋 메시지는 결과가 드러나게 작성한다.
- PR에는 테스트 결과, 관련 Issue, 리뷰 포인트를 기록한다.
